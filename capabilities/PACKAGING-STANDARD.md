# 📐 能力封装规范（Packaging Standard）

> 新增/升级任何能力包时，**必须**按本规范声明字段。缺项 = 不合格。

## 一、必备字段（8 项）

| # | 字段 | 说明 | 示例 |
|:-:|------|------|------|
| 1 | **名称 / 域** | 能力名 + 所属域 | `joe-admissions` / 🎓升学 |
| 2 | **触发词** | 用户说什么会调用它 | "选校""检查升学时间线" |
| 3 | **技能文件** | SKILL.md 路径 + 版本 | `skills/joe-sub-agents/joe-admissions/` |
| 4 | **数据源** | 只读哪些权威来源（**必须可追溯**） | STATE.md / awards.md / 官方成绩单 |
| 5 | **工作流** | 分步 SOP（可执行、可重复） | 选校调研 4 步 |
| 6 | **验证方式** | 怎么证明做对了 | 双副本 diff / 线上 HTTP 200 / 读回 |
| 7 | **交付渠道** | 产出送到哪 | 家庭群 / GitHub / .ics |
| 8 | **升级记录** | 版本 + 变更日志 | `CHANGELOG.md` |

## 二、质量约束（写进每个能力包）

- ❌ **禁止编造**：没有来源的数字/名称/截止日 → 写"待核实"
- ❌ 禁止把"推测"写成"事实"（如需推测，显式标注"推测/待确认"）
- ✅ 外部事实（学校要求、赛事名称、成绩）→ **官方来源核实**
- ✅ 派发子任务必须注入 SOP（身份/任务/验证/禁止/完成标准）
- ✅ 重大决策（费用、申请策略、对外联络）→ **家主拍板**

## 三、升级检查清单（每次变更后逐项打勾）

- [ ] 双副本一致（`diff joe-growth/<f> joe-growth-tracker/<f>`）
- [ ] `main` 与 `gh-pages` 零差异（`git diff main gh-pages --stat` 为空）
- [ ] 线上实测（HTTP 200 / 内容抽查 / 数据.js 数值）
- [ ] STATE.md 已记录（关键数据 + 巡检/台账行）
- [ ] `capability_index.json` 版本与内容已更新
- [ ] `CHANGELOG.md` 已追加
- [ ] 涉及的旧名称/旧口径已全局更正（`grep` 残留检查）

## 四、反例（曾经踩过的坑）

| 坑 | 教训 |
|----|------|
| 从 `/root/joe-growth-tracker` 直接 git push | 该目录**无独立 .git**，会上溯到 `/root`（物流仓库）→ 只用 `joe-growth` 推送 |
| 用默认 `open()` 读写 .ics | universal newlines 会**吃掉 CRLF** → 必须 `newline=""` |
| 把"推测"当成已知（如"Penny老师"） | 名称/角色必须来自确切来源，写"待确认" |
| 记账重复计（半年费已含在年费内） | 计费口径先确认，**宁可少记不重复记**，并显式标注 |
| 只改一处就交差 | 全库 grep 旧值 → 全部同步（含双副本、网站、日志） |
