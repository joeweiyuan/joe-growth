### 0.3 真题是**有版权差异**的（这决定"能不能承诺真题"）

不同考试能拿到的"真题"完全不是一个量级，这一列必须在设计里写死，否则就是骗人：

| 考试 | 官方公开题源 | 可得性 |
|:----|:----|:----|
| **AP** | College Board AP Central 历年 FRQ + Scoring Guidelines | ✅ 官方免费，量大 |
| **A-Level** | CAIE / Edexcel 官网 Past Papers + Mark Schemes | ✅ 官方免费，量极大 |
| **SAT** | College Board Bluebook 官方练习 + 官方题库（Question Bank） | ✅ 官方免费 |
| **ACT** | 官方 Free Practice Test（全套）+ 官方指南 | 🟡 官方免费 1 套 + 付费若干 |
| **TOEFL** | ETS 官方免费练习题 + TOEFL Practice Online（付费） | 🟡 免费少、TPO 付费 |
| **IELTS** | 官方免费样题 + Cambridge Authentic Practice Tests（需购买） | 🟡 免费少、书需买 |
| **IB** | 官方 Specimen Papers + Subject Briefs；**Past Papers 不公开**（学校经 IBIS 获取） | 🔴 真题不可公开获取 |

> 📌 所以架构里必须有**两种出题模式**：
> - `mode: released`（官方放出的真题）→ 标注来源与年份
> - `mode: equivalent`（按官方 blueprint 造同规格题）→ **明确标注"非真题"**，绝不打真题旗号

## 2. 总体架构：1 个底座 + 3 层

```
┌─────────────────────────────────────────────────────────┐
│  L0 底座：academic-exam-core（7 个考试包共用，只建一次）      │
│  官方题源登记 · 考纲映射 · 题库 schema · 评分 rubric         │
│  出题规范 · 批改规范 · 版本与生效日期 · 溯源审计              │
└─────────────────────────────────────────────────────────┘
        │                    │                    │
┌───────▼───────┐   ┌────────▼────────┐   ┌───────▼────────┐
│ L1 学术考试(7) │   │ L2 兴趣特长(2)   │   │ L3 专项数据(1)  │
│ AP / IB       │   │ 竞赛科创         │   │ 声学聚合数据     │
│ A-Level       │   │ 体育艺术         │   │                │
│ TOEFL/IELTS   │   │                 │   │                │
│ SAT / ACT     │   │                 │   │                │
└───────────────┘   └─────────────────┘   └────────────────┘
```

**为什么要有 L0 底座**：7 个考试包如果各写各的，会出现"AP 说 5 分制、IB 说 7 分制、A-Level 说 A*"三套互不相通的逻辑，改一处要改七处。底座把**共同动作**（登记来源、出题、批改、版本）抽象一次。

## 3. L0 底座：academic-exam-core

| 模块 | 内容 |
|:----|:----|
| **source registry** | `sources.yaml`：每条题源必须有 `url / 类型（official-exam/official-sample/third-party）/ 抓取日期 / 适用考季 / 版权状态`。**没有 url 的材料不得进入题库** |
| **syllabus map** | 统一知识树：`exam → subject → unit → topic → 认知层级（记忆/理解/应用/分析）` |
| **item schema** | 单题 JSON：题干、选项、答案、**rubric/采分点**、难度、认知层级、topic 标签、来源、是否真题 |
| **blueprint** | 每场考试的试卷结构（题量、时间、板块配比、分值）→ 出题按 blueprint 组卷 |
| **generator** | 输入：`exam + subject + topic + 难度 + 题量 + mode(released/equivalent)` → 输出成品卷（PDF/Word，含答案与 rubric） |
| **grader** | 输入：学生答案 → 按官方 rubric 逐点判分 + 错因归类（概念/计算/规范/审题）→ 回写错题本 |
| **version guard** | 考纲改版（如 AP 2025 改革、SAT 机考、TOEFL 6 分制）→ 旧题标 `deprecated`，不混用 |

**质量门（硬约束）**
1. 真题必须带 `source_url + 年份 + 题号`，缺一不可；
2. `equivalent` 题必须在卷首注明"按官方 blueprint 命制，非真题"；
3. 批改必须引用 rubric 条款，不允许"感觉给分"；
4. 考纲版本必须与考季匹配，跨版本混卷 = 直接判废。

## 4. L1：7 个学术考试包（统一 6 项能力）

| # | 能力 | AP | IB | A-Level | 新托福 | 雅思 | SAT | ACT |
|:-:|:----|:--|:--|:--|:--|:--|:--|:--|
| 1 | **官方标准**（考纲/评分/报名/日程） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 2 | **年级-知识地图**（每科每单元知识点） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 3 | **科目大类全景**（有哪些科、怎么选） | ✅ | ✅ | ✅ | — | — | — | — |
| 4 | **升学要求矩阵**（国家×专业→必须修什么） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 5 | **题源 + 出题引擎**（真题/等价题） | ✅ | 🟡 | ✅ | 🟡 | 🟡 | ✅ | 🟡 |
| 6 | **批改与诊断**（rubric 判分 + 错因归类） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

### 4.1 第 4 项是重点：升学要求矩阵

这一项直接服务"走 AP 升学，哪些必须修"。设计成三维表：

```
国家/地区（美/英/欧/澳/港/新）
   × 专业方向（STEM/商科/人文/艺术/医学）
      → 推荐组合（例：美本 STEM = AP Calc BC + AP Physics C + AP CS A + AP Chem/Bio）
      → 最低要求 / 竞争力要求（两档分开，避免把"建议"说成"必须"）
      → 证据来源（大学官网 admission 页面 + 官方 policy）
```

⚠️ **诚实边界**：除少数学校（如英国 G5 对 A-Level 有明确科目要求、部分美国大学给 AP 学分表）外，**绝大多数美本不"要求"特定 AP 科目**——所以矩阵必须分两列：
- `required`（白纸黑字的要求，带 url）
- `recommended`（竞争力画像，标注为"统计/建议"，不冒充要求）

### 4.2 各包的关键差异（不能一套逻辑套七次）

| 考试 | 评分体系 | 关键差异点 |
|:----|:----|:----|
| AP | 1–5 分 | 5 月统考；FRQ 有官方 rubric；可换大学学分 |
| IB | 1–7 分/科 + TOK/EE 加分，满分 45 | **IA（内部评估）+ EE/TOK 是校内作业**，不是考试，要单独管 |
| A-Level | A*–E（部分 U/MS） | AS 与 A2 分两年；**不同考试局（CAIE/Edexcel/AQA）大纲不同**，必须分 exam board |
| 新托福 | **6 分制**（2026 改革后） | 与旧 120 分制换算；口语是录音评分 |
| 雅思 | 1–9 分（0.5 档） | 学术类 vs 培训类；写作 Task1/2 分开评分 |
| SAT | 400–1600（机考自适应） | Module 1/2 自适应；语法与数学合并计分 |
| ACT | 1–36（四科 + 写作选考） | 科学推理是独立科目；节奏极快 |

## 6. L3：`acoustics-data-pack`（声学聚合数据收集整理）

### 6.1 模块设计

| # | 模块 | 做什么 |
|:-:|:----|:----|
| 1 | **数据源接入** | 设备类型（声级计/手机/录音笔/传感器阵列）、采集协议（手工 CSV/串口/MQTT/API）、目录约定 |
| 2 | **元数据标准化** | 必填：时间戳（含时区）、测点 ID 与坐标、设备型号与序列号、**校准记录**、采样率/位深、环境（温湿度/风速/背景噪声） |
| 3 | **质量校验** | 削波检测、静音段、直流偏移、信噪比、采样率一致性、**校准漂移**、缺失时段 |
| 4 | **聚合对齐** | 多设备时间对齐、单位统一（dB(A)/dB(Z)/dB(C)）、重采样、去重（同内容哈希） |
| 5 | **指标计算** | Leq、Lmax/Lmin、L10/L50/L90、1/1 与 1/3 倍频程、A/C 计权、频谱图 |
| 6 | **产物输出** | 标准数据集（CSV/Parquet）+ **数据字典** + 质量报告 + 图表 + 可复现脚本 |
| 7 | **合规** | 人声/隐私脱敏、校准溯源、原始数据只读留存 |

### 6.2 可直接复用 vs 需补足

| 项 | 状态 | 说明 |
|:----|:----|:----|
| 采集→清洗→入库流程骨架 | ✅ 复用 `data-capture` | 只借流程，不借内容 |
| 统计分析口径 | ✅ 复用 `data-science` | 异常值、分布、置信区间 |
| 音频转码/切片/重采样 | ✅ 复用 `media` + **ffmpeg 6.1.1** | 现成 |
| WAV 读写 + FFT + 统计 | ✅ **numpy 2.5.1 + scipy 1.17.1 已装** | 可直接算 Leq/频谱 |
| `librosa`（高级声学特征） | ❌ 需装 | 约 60MB，含依赖 |
| `soundfile`（多格式音频） | ❌ 需装 | 轻量 |
| `pandas / matplotlib`（数据集与图表） | ❌ 需装 | 报表与可视化必需 |
| **标准依据**（如环境噪声测量/声功率级测定） | ⚠️ **需逐条核实** | 必须登记标准号+版本+条款，**不凭记忆写** |
| 设备协议手册 | ⚠️ 需您提供 | 具体声级计型号的导出格式 |
| 校准规程 | ⚠️ 需您提供 | 校准器型号、校准周期 |

> 📌 声学包最容易出事的地方不是算法，是**元数据缺失**（没记校准值、没记测点、时区错）——所以模块 2 设计成"缺字段拒收"，而不是"事后猜"。
